# WorkSpace — REST API Overview & Endpoints Reference

This document provides a technical reference for the HTTP REST API exposed by the WorkSpace backend at `/api/v1`.

The authoritative high-level specification is maintained in [`PROJECT_SPEC.md`](PROJECT_SPEC.md).

---

## 1. General Principles

### 1.1 Base URL & Content Negotiation
- **Base URL:** `http://localhost:5000/api/v1` (configurable via `PORT` in `.env`)
- **Headers:** All requests sending data must specify:
  ```http
  Content-Type: application/json
  Accept: application/json
  ```

### 1.2 Authentication
All secured endpoints require an HTTP Bearer token in the `Authorization` header:
```http
Authorization: Bearer <JSON_WEB_TOKEN>
```
Tokens are generated by `/api/v1/auth/login` or `/api/v1/auth/register` and signed with HMAC-SHA256 using `JWT_SECRET`.

### 1.3 Standard Response Envelopes

#### Success Envelope (`200 OK`, `201 Created`)
```json
{
  "success": true,
  "data": { ... },
  "timestamp": "2026-11-05T10:00:00.000Z"
}
```

#### Error Envelope (`400`, `401`, `403`, `404`, `409`, `429`, `500`)
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable explanation of error",
    "details": { "field": "Specific validation failure" }
  },
  "timestamp": "2026-11-05T10:00:00.000Z"
}
```

## 2. API Endpoints Directory

### 2.1 Health Check

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/health` | Public | Returns system uptime and MongoDB connectivity state. |

---

### 2.2 Authentication & User Profiles (`/auth` & `/users`)

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/auth/register` | Public (Rate-limited) | Registers a new account with global role `USER`. Returns JWT and user object. |
| `POST` | `/auth/login` | Public (Rate-limited) | Authenticates email and password. Returns JWT and user object. |
| `GET` | `/auth/me` | Authenticated | Returns current authenticated user profile and permissions. |
| `GET` | `/users/me` | Authenticated | Alias to `/auth/me`. |
| `GET` | `/users/eligible-managers` | **Admin Only** | Returns active users eligible to be assigned as primary project managers. |

---

### 2.3 Projects & Memberships (`/projects`)

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/projects` | Authenticated | Lists projects (Admins see all; members see joined; non-members see public metadata). |
| `POST` | `/projects` | **Admin Only** | Instantiates a new project and assigns the initial primary manager. |
| `GET` | `/projects/:id` | Authenticated | Detailed project information for members; public metadata for non-members. |
| `PATCH` | `/projects/:id` | **Admin Only** | Updates project name or description. |
| `PATCH` | `/projects/:id/visibility` | **Admin Only** | Toggles project visibility between `PUBLIC` and `PRIVATE`. |
| `PATCH` | `/projects/:id/primary-manager` | **Admin Only** | Reassigns primary manager with automatic member demotion. |
| `GET` | `/projects/:id/members` | Authenticated | Lists active team members in the project. |
| `DELETE` | `/projects/:id/members/:userId` | **Admin / PM** | Removes an employee from project membership. |
| `GET` | `/projects/:id/activity` | Project Members | Returns paginated audit activity stream for the project. |

---

### 2.4 Invitations & Onboarding (`/invitations`)

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/invitations` | **Admin / PM** | Generates a 32-byte cryptographically secure invitation link. |
| `POST` | `/invitations/accept` | Authenticated | Unified endpoint consuming an invitation token and granting membership. |

---

### 2.5 Join Requests (`/projects/:id/join-requests` & `/join-requests`)

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/projects/:id/join-requests` | Authenticated Non-Members | Submits a pending request to join a public project. |
| `GET` | `/projects/:id/join-requests` | **Admin / PM** | Lists pending join requests for the project. |
| `PATCH` | `/join-requests/:id/approve` | **Admin / PM** | Atomically approves request, creates membership, and notifies user. |
| `PATCH` | `/join-requests/:id/reject` | **Admin / PM** | Atomically rejects request with optional reason. |

---

### 2.6 Kanban Tasks & Comments (`/projects/:id/tasks` & `/tasks`)

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/projects/:id/tasks` | Project Members | Fetches all tasks in project ordered by `status` and `position`. |
| `POST` | `/projects/:id/tasks` | **Admin / PM** | Creates a new task in a specified column. |
| `GET` | `/tasks/:id` | Project Members | Retrieves detailed task record. |
| `PATCH` | `/tasks/:id` | **Admin / PM** | Updates title, description, priority, assignee, or due date. |
| `PATCH` | `/tasks/:id/status` | **Assignee / PM / Admin** | Updates task column status and fractional position (OCC protected). |
| `DELETE` | `/tasks/:id` | **Admin / PM** | Deletes a task card from the board. |
| `GET` | `/tasks/:id/comments` | Project Members | Lists chronological discussion comments on a task. |
| `POST` | `/tasks/:id/comments` | Project Members | Posts a new comment on a task. |

---

### 2.7 Real-Time Conversations & Chat (`/conversations`)

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/conversations/project/:projectId` | Project Members | Retrieves or initializes the project group conversation. |
| `GET` | `/conversations/admin-pm/:managerId` | **Admin / PM Only** | Retrieves or initializes an isolated Admin–PM 1-on-1 private direct message. |
| `GET` | `/conversations/:id/messages` | Conversation Participants | Returns paginated message history. |
| `POST` | `/conversations/:id/messages` | Conversation Participants | Submits a message and triggers real-time WebSocket broadcast. |

---

### 2.8 Notifications (`/notifications`)

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/notifications` | Authenticated | Retrieves current user's notifications. |
| `GET` | `/notifications/unread-count` | Authenticated | Returns count of unread notifications for badge display. |
| `PATCH` | `/notifications/:id/read` | Authenticated Recipient | Marks a specific notification as read. |
| `PATCH` | `/notifications/read-all` | Authenticated Recipient | Marks all notifications for user as read. |

## 3. Rate Limiting Envelopes

The API enforces tiered rate limiting across IP addresses via `express-rate-limit`:

| Tier | Window | Limit | Target Endpoints | Error Code on Breach |
|---|---|---|---|---|
| **Login Limiter** | 15 minutes | 10 requests | `POST /api/v1/auth/login` | `RATE_LIMIT_EXCEEDED` (`HTTP 429`) |
| **Registration Limiter** | 15 minutes | 10 requests | `POST /api/v1/auth/register` | `RATE_LIMIT_EXCEEDED` (`HTTP 429`) |
| **Invitation Limiter** | 15 minutes | 30 requests | `POST /api/v1/invitations/*` | `RATE_LIMIT_EXCEEDED` (`HTTP 429`) |
| **Global API Limiter** | 15 minutes | 300 requests | All other `/api/v1/*` routes | `RATE_LIMIT_EXCEEDED` (`HTTP 429`) |

## 4. Standard Error Codes Reference

| Error Code | HTTP Status | Typical Cause |
|---|---|---|
| `UNAUTHORIZED` | 401 | Missing, malformed, or invalid Bearer token. |
| `TOKEN_EXPIRED` | 401 | JWT signature expired. |
| `INVALID_CREDENTIALS` | 401 | Incorrect email or password during login. |
| `FORBIDDEN` | 403 | Insufficient permissions (e.g. standard member calling Admin routes). |
| `ACCOUNT_INACTIVE` | 403 | Deactivated account attempting access. |
| `NOT_FOUND` | 404 | Target resource ID does not exist. |
| `DUPLICATE_EMAIL` | 409 | Registering with an existing email. |
| `VERSION_CONFLICT` | 409 | Task OCC version mismatch during concurrent updates. |
| `ALREADY_RESOLVED` | 409 | Join request has already been approved or rejected. |
| `VALIDATION_ERROR` | 400 | Request body failed Zod schema checks. |
| `RATE_LIMIT_EXCEEDED` | 429 | Exceeded allowable requests in the 15-minute window. |
| `INTERNAL_SERVER_ERROR` | 500 | Unhandled server error. |
